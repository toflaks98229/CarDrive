## 먼저 배제한 것 — 카메라

씬 카메라는 near 0.1 · far 340 입니다. 비가 3,400 이고 URP 는 역방향 부동소수 깊이를
쓰므로, 이 범위에서 3~10 m 짜리 건물이 깜빡일 정밀도 문제는 **생기지 않습니다.**
카메라를 만질 이유가 없었습니다.

## 원인 셋

### 1. 창 테두리의 모서리 겹침 (`hardsurface.reveal`) — 가장 큼

테두리 넷을 세울 때 **세로가 가로 자리까지** 올라가 있었습니다.

```python
# 전
put(sign * (w + jamb) * 0.5, nose, 0.0, jamb, thick, h + jamb * 2.0, mat)   # 세로
put(0.0, nose, sign * (h + jamb) * 0.5, w + jamb * 2.0, thick, jamb, mat)   # 가로
```

세로가 `h + jamb*2`, 가로가 `w + jamb*2` 라 **네 모서리에서 두 상자가 같은
`jamb × jamb` 기둥**을 차지합니다. 두 상자의 앞면·뒷면이 같은 평면에서 같은 쪽을
보므로 깊이 버퍼가 못 정합니다.

**고침:** 세로를 `h` 까지만. 모서리가 겹침이 아니라 **맞대기**가 됩니다.

House04 249쌍 중 약 200쌍이 이것이었습니다.

### 2. 방 벽 넷이 모서리에서 같은 기둥을 차지함 (`build_interiors.wall`)

벽마다 `-half - WALL` 에서 `+half + WALL` 까지 나가 있었습니다. 넷이 다 그러면
모서리의 `WALL × WALL` 기둥을 **두 벽이 함께** 차지합니다.

**고침:** 좌우 벽만 모서리까지 내보내고 앞뒤 벽은 안쪽에서 멈춥니다.

```python
grow = WALL if axis == 0 else 0.0
```

### 3. 개구부 인방이 벽면과 같은 평면 (`build_interiors.wall`)

인방(구멍의 어두운 속)이 **바깥면은 벽면과 같은 평면**, **밑면은 구멍 위 벽의
밑면과 같은 높이**였습니다. 둘 다 고쳤습니다 — 바깥면을 6 cm 안으로 들이고,
밑면을 6 cm 내렸습니다. **실제 인방도 구멍보다 내려와 걸칩니다.**

# 2차 — 숫자 정정과 스파인 (2026-09-10)

## ⚠ 앞의 "558쌍 → 1쌍" 은 틀린 수치였습니다

`build_buildings.run()` 은 집마다 `hardsurface.wipe()` 로 씬을 비웁니다. 그래서 `run()`
직후에 씬을 재면 **마지막 한 채밖에 없습니다.** 제가 그 한 채를 재고 여섯 채라고 읽었습니다.

**디스크의 blend 를 여는 `Z.main()` 이 맞는 수치입니다.**

또 하나 — `run()` 은 FBX 만 내보내고 **blend 는 저장하지 않습니다.** 저장은 `lay_out()` 이
합니다. 셋(건물·실내·스파인) 다 같은 구조입니다. 재기 전에 반드시 둘 다 부르십시오.

```python
mod.run()      # FBX
mod.lay_out()  # blend 저장
```

## 창 간격보다 테두리가 넓었습니다 — 남아 있던 진짜 원인

`reveal` 모서리를 고친 뒤에도 House04 에 96쌍이 남았습니다. 같은 크기의 면이
쌍으로 잡히는 것이 단서였습니다.

테두리는 창보다 좌우·위아래로 `jamb`(0.22 m)씩 넓습니다. 그런데 창을 칸 간격
(`pitch = bw / bays`)에 맞춰 놓으니 **테두리 폭 `w + 0.44` 가 간격을 넘어** 옆 창의
테두리와 겹쳤습니다. 세로로는 위층 창과 겹쳤습니다.

**고침:** 창을 먼저 자릅니다.

```python
ww = min(ww, pitch - JAMB * 2.0 - 0.12)
wh = min(wh, storey - JAMB * 2.0 - 0.12)
```

## 감사가 안 보이는 것까지 세고 있었습니다

시타델 1,217쌍 중 **540쌍이 허위**였습니다. 세로 살과 가로 띠는 벽면에서 시작해
바깥으로 나오므로, **덩어리 안쪽을 보는 면들**이 같은 평면에서 겹칩니다. 그 앞을
벽이 막고 있어 절대 그려지지 않습니다. 코드 주석이 이미 그렇게 적어 두었는데
감사가 그것을 몰랐습니다.

`audit()` 에 **파묻힘 판정**을 넣었습니다 — 겹친 사각형이 반대쪽을 보는 면 하나에
통째로 들어가면 두 고체가 맞댄 속이므로 셈에서 뺍니다.

⚠ 이 판정은 **파츠를 합쳐서 봐야** 듣습니다. 벽과 껍질이 다른 오브젝트라, 오브젝트
하나만 보면 막아 주는 벽을 못 봅니다. `main()` 은 프리셋 단위로 합치므로 맞습니다.

## 형상 결함 다섯

### 1. 갤러리 두 벌이 같은 부피에 있었습니다 (823 m²)

스파인은 옆구리에 **자기 갤러리**를 갖고 있습니다(`y = ±64`). 시타델의 단이 물려
올라가다 **둘째 단**에서 테라스 가장자리가 `y = ±63` 에 떨어졌습니다. 거기 붙은
갤러리가 스파인 갤러리 **한가운데**에 들어앉은 것입니다.

깜빡인 것은 슬롯 기둥 옆면(`x = ±0.80`)이지만, 실제로는 통로·난간·문틀까지
**한 벌이 통째로 다른 한 벌 속에** 있었습니다.

**고침:** `clear_of()` 를 만들어 갤러리를 **안쪽으로** 비켜 세웁니다. 바깥으로 밀면
허공이지만 안쪽에는 아래 단의 테라스가 있어 실제로 설 자리가 됩니다.

```python
capsules(..., y_half=clear_of(d * 0.5, W * 0.5), ...)
```

### 2. 갤러리 통로가 층 슬래브와 같은 자리에서 끝났습니다 (140 m², 636쌍)

둘 다 `inner` 만큼 길어 마구리가 `x = ±61.6` 에서 같은 평면이었습니다. 낱장은
0.22 m² 인데 **층마다 양쪽 양끝**이라 시타델에서만 636쌍이 나왔습니다.
여기는 이음매 **안쪽**이라 옆 프리셋이 가려 주지도 않습니다.

**고침:** 통로를 0.6 m 짧게. 구조인 슬래브가 디딤판보다 조금 나온 것이 되어
오히려 맞습니다.

### 3. 샤프트의 어두운 덮개가 가장자리 보와 같이 끝났습니다 (277 m²)

층 바닥의 어두운 덮개와 가장자리 보가 둘 다 `span_y ± 9.8` 에서 끝났습니다.
층마다 두 쌍, 열세 층입니다.

**고침:** 덮개를 보 **사이**에서 끊습니다. 가장자리를 보 하나가 도맡으니
"판" 이라는 말이 오히려 또렷해집니다.

### 4. 경사로 다리가 참 속에 박혀 있었습니다 (25 m²)

다리와 마지막 참이 **두께도 높이도 같아서**(둘 다 1.6 m, `z = 33.8~35.4`)
윗면과 밑면이 같은 평면에서 겹쳤습니다. 데크 밑에서 올려다보면 보이는 자리입니다.

**고침:** 다리를 참 앞에서 멈춥니다. 메워야 할 것은 데크와 참 사이의 틈뿐입니다.

### 5. 갠트리 다리가 레일과 같은 높이에서 시작했습니다 (15 m²)

레일과 다리의 밑면이 같은 평면에서 같은 쪽(아래)을 보았습니다. 이 둘은 데크
**바깥으로** 5 m 나가 있어 밑에 데크가 없습니다 — 정말 보이는 자리였습니다.

**고침:** 다리를 레일 **위에서** 시작합니다. 갠트리는 원래 레일을 타고 다닙니다.

### 덤 — 꼭대기 띠 (32 m²)

`endwall` 의 맨 위 가로 띠는 단 꼭대기를 **걸치고** 서서 `top + 0.8` 까지 올라오는데,
마지막 단의 띠가 x 로 `±36.6` 이라 꼭대기 띠와 같은 평면이었습니다. 띠를 0.6 m 올렸습니다.

## 감사가 또 두 가지를 몰랐습니다

둘 다 **다른 메시에 가려지는데 감사가 그 메시를 안 보는** 경우입니다.

### 이음매 평면 (`seam`)

프리셋은 x 로 줄줄이 맞물립니다. 그래서 양 끝 단면은 **옆 프리셋 속**입니다 —
데크 마구리와 노면 마구리가 거기서 같은 평면을 쓰지만 게임에서는 둘 다 안 보입니다.
`SM_Mega_Core` 에서만 **40 m²** 가 허위였습니다.

⚠ 이 규칙은 **스파인 프리셋에만** 줍니다. 집과 실내는 혼자 서 있습니다.

### 소켓의 바닥 (`under`)

난간 밑동과 갤러리 기둥 밑면이 `z = 35.2` 에서 같은 평면을 쓰는데, **둘 다 데크에
눌려** 안 보입니다. 그런데 데크는 `SM_Mega_Core` 라는 **다른 메시**입니다 — 한 베이짜리
하나를 베이마다 되풀이해 깔아 놓은 것이라 프리셋 무리에 안 들어옵니다.

`socket_floor()` 가 소켓에서 **한 베이를 꽉 채우는 면만** 골라 x 로 늘여 놓고,
`audit(under=...)` 가 그것을 **가려 주기만 하는 면**으로 씁니다. 결함으로는 안 셉니다.

⚠ 베이를 다 안 채우는 것(기둥, 다리)은 버립니다. 그것을 늘여 놓으면 있지도 않은
자리를 가려 준다고 우겨 **진짜를 놓칩니다.**
